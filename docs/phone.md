# Streaming to the phone

Apollo, the phone's virtual display, parking the cursor, keeping the phone's display clear, Apollo's status, and Open on (`src/phone-display.ts`, `src/park-cursor.ts`, `src/keep-phone-clear.ts`, `src/apollo.ts`, `src/open-on-display.ts`, main process).

## Streaming (Milestone 4)

Apollo on the PC, Artemis on the user's Android phone. Apollo adds a virtual display the phone's size while streaming and streams only that. `src/phone-display.ts` (main) moves the portrait onto it and makes it full screen, and puts it back on the PC when it's removed (watches `screen` display events, debounced). The display is recognized by its adapter name (`/SudoMaker|SudoVDA/i`, via `displayAdapterAt()` in `win32.ts`: `MonitorFromPoint` → `GetMonitorInfoW` → `EnumDisplayDevicesW`), never by shape (the user's HP 727pq monitor is portrait) or label (Apollo names it after the client). Main broadcasts `phone-display-changed`; the picker shows a status pill (`src/phone-status.ts`) and the portrait gets an `on-phone` class (hides the mouse pointer, since taps arrive as mouse input and would show it jumping; a mouse paired with the phone shows it while moving: `pointer-shown`, set in portrait.ts after `MOVES_TO_SHOW` (3) moves in a row with no button held covering `TRAVEL_TO_SHOW` (24 px), removed after `HIDE_AFTER` (2 s) still; a mouse press in the reader, on the PC too, hides it at once with `pointer-hidden` until the mouse moves like that again). In the reader every click outside the corner buttons moves the game on, so a mouse works as a clicker wherever its pointer is: the whole text zone (window, name tag, page and the space around them) clicks the text box (the page's corner in full-screen text), and the background picture clicks the game where tapped, falling back to the text box off the picture.

While the portrait is on the phone, each such tap (`clickGame(point, park)`, `ParkSpot` 'text' or 'page'; not Auto's clicks, not Menus mode) then **parks the real cursor on the game** (`src/park-cursor.ts`, main: `parkSpot` points it `INSET` (2 px) inside the bottom-right corner of the text box, or full-screen text's page, so the click lands in the box while the cursor's picture, drawn right of and below its tip, lies outside what OCR reads; left of the box was tried first, but a game's quick menu (V.BOOKM, SAVE, Q.SAVE, Q.LOAD, EXIT) popped up there on hover, over the text, and was read into the line; `parkCursor()` in win32.ts also brings the game to the front, so the click isn't caught by a window over it): off the phone's display, so the stream never shows it, and the mouse's next clicks go straight to the game. Until the cursor leaves the game's client area, main polls the left button every 30 ms (`GetAsyncKeyState`, ignoring main's own clicks via `asOwnClick`) and sends `game-clicked`, which the portrait notes as a tap for Auto. Not yet tested on the phone.

Leaving Artemis without quitting only _pauses_ the session, and Apollo keeps the display while paused, so the portrait would stay out of sight on it: the picker's PC / Phone switch (`#portrait-place`, radio buttons styled as one pill by the `.switch` class; `set-portrait-on-phone` → `setOnPhone`) moves it between the two while the display exists (`PhoneDisplay.portraitOnPhone`). Back on the PC, the portrait keeps its left edge and shape but takes the picker's top edge and height (`toHeightOf`, with the picker passed in as `heightGuide`); `setBounds` is called twice there, because crossing from the phone's display (100% scaling) to the PC monitor (150%) rescales the window after the first call. The switch is always shown and is saved straight away as an **app setting** (`src/settings.ts`: `settings.json` in `userData`, laid over defaults on load, no Save button; `get-`/`set-portrait-on-phone`), so it stays on PC even when the phone connects. The **Button size** slider (Sizes, `buttonSize`, sent to the portrait as `--button-size`) is another app setting; it's saved with the Save button, like the game's settings (see the Menus sheet's Sizes). Corner buttons are sized in `vmin` with no `rem` cap, because the phone's display is far more CSS pixels wide than the PC window (100% vs 150% scaling).

The portrait window has Windows' `EdgeGesture_DisableTouchWhenFullscreen` property set (`blockEdgeSwipesWhenFullScreen()` in `win32.ts`, a COM property-store call through koffi), because swiping up to leave Artemis also reaches the PC as a touch swipe from the bottom edge, which would raise the taskbar.

Above the phone status, the picker shows whether Apollo's Windows service (`ApolloService`) is running, with **Start** while stopped (`StartServiceW`, or `sc start` run as admin via `ShellExecuteW` `runas` when the service doesn't let this account start it) and **Settings** (Apollo's web page); `src/apollo.ts` in main, polled every 2 s, `apollo-changed`; `src/apollo-status.ts` in the picker; how to let the account start it without a prompt is in getting-started.md.

Under the theme button, the picker's **Open on** switch (`#open-on`, Main / another monitor's name, with a select when there are several others; `src/open-on.ts`) is an app setting (`openOn` in `settings.json`: `{ on, monitor }`, the monitor by Electron's `label`, since display IDs change when monitors go off and on; saved straight away; `list-monitors`, `get-`/`set-open-on`, `monitors-changed`): while on, the picker and portrait open on that monitor (`createWindows`), turning it on moves them there as a group (`moveAppWindows`; the portrait not while it's on the phone), and a game started from the app is moved there as each of its windows appears (`moveGameWindow`, keeping its size; `windowBounds`/`moveWindow` in win32.ts). For the user's LG OLED main display, turned off while the PC is left on. Other programs still open on the main display (the user's choice). `src/open-on-display.ts` in main; Apollo's virtual display is never listed (`isPhoneDisplay`, exported from phone-display.ts).

While the phone's display exists, nothing but the portrait may be on it (the user's choice): every second `src/keep-phone-clear.ts` (main) lists program windows (`programWindows()` in win32.ts: `EnumWindows`, shown, not minimized or cloaked, titled, not tool/click-through/no-activate windows, the taskbars or the desktop) and moves any reaching more than `MIN_OVERLAP` (16 px, by the visible frame, `visibleBounds`, since a maximized window's invisible borders reach past its monitor) onto a real monitor: the one it's mostly on, nudged inside, or, wholly on the phone's, the Open on monitor or the main display, centered; shrunk to fit one monitor, and maximized again if it was (`placeWindow`, `restore`, `maximize`). The picker counts as another window. Admin programs' windows can't be moved. Not yet tested with the phone connected. Not a duplicate view on purpose: that would need a second portrait window, with a second capture and a second OCR reader.
