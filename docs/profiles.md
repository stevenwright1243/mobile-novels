# Game profiles, regions and spots

What the app saves per game (`src/profiles.ts`, `GameProfile` in `src/declarations.d.ts`): regions, spots, sizes and the rest, how saving works, and the name box's reader.

## Profiles

Each game has a **profile** (`GameProfile` in `src/declarations.d.ts`): one JSON file per game in `%APPDATA%\mobile-novel\games\` (`app.getPath('userData')`), handled by `src/profiles.ts`. It holds the exe path, title, an optional short `name` (shown instead of the title in the Menus sheet's Visual Novels; the picker's **Short name** box in its top bar, `#game-name`, `set-game-name`/`game-name-changed`, an unsaved edit like the rest, empty for none; `snapshot` keeps it as `null` when unset, since JSON drops `undefined`), click method, background height (`backgroundY`, where the background sits top to bottom; the Sizes slider; the picker's Portrait view box in `src/background-view.ts`), text style (`size`, a multiplier on the message window's font size, and `nameSize`, the name tag's size relative to the text, sent to the portrait as `--name-size`; Sizes sliders), regions, client-area size and last-played time. Format `version: 3`. Settings made of several values (`regions`, `textStyle`) are laid over their defaults on load, so fields added later get defaults without a version bump. Older version-2 files (named after the window title) are upgraded in memory on pick, keeping their regions, and the old file is deleted on first save. Profiles are keyed by the lowercase `.exe` name (`exePathOf()` in `win32.ts`), falling back to `title:<window title>` if the exe can't be read. Main holds the picked game's `profile` and replaces it immutably on each change. **Saving is manual** (the user's choice): edits apply live, but nothing is written until the picker's Save button or Ctrl+S (`save-profile`). Unsaved edits are detected by comparing against `savedSnapshot`. Switching games or closing the picker with unsaved edits shows a Save / Don't save / Cancel dialog (`resolveUnsavedEdits`). Saves are announced with `profiles-changed`, and the button state with `save-state-changed`. Right-clicking a game row opens a native menu (`show-profile-menu`, built with `Menu.buildFromTemplate` in main) with Pick / Show file in folder / Delete (confirmed with a dialog). Rows that can't be started (no .exe saved) use `aria-disabled`, not `disabled`, so they still receive right-clicks. The picker's "Your games" list comes from `list-profiles`, which marks each profile open/closed by matching the exes of open windows. Regions are fractions (0 to 1) of the game's **client area** (the window minus title bar, borders and menu bar), never of the whole capture and never screen pixels. Renderers convert using the client area from `window.vn.getClientArea()`. Currently `background`, `text`, `name` (the name box: who's speaking) and `page` (where full-screen text goes; defaults to the whole game less a 1–2% margin, since text touching the crop's edge is cleared; picker button **Edit full-screen text**, its outline shown only while it's edited and left out of snapping); button regions are deferred. Beside the regions, the profile has **spots** (`points`: `Points`, a `GamePoint` or null per `PointName`, fractions of the client area like regions, laid over `DEFAULT_POINTS` on load, `get-points` / `set-point` / `points-changed`, part of the unsaved edits): `quickSave` and `quickLoad`, the game's own quick save and quick load buttons, placed in the picker with **Place q.Save** / **Place q.Load** (region-editor.ts's `placing`, beside `editing`: click or drag in the preview puts the spot there, the edit panel shows only X and Y via its `placing` class hiding `.box-only`, arrow keys nudge; each shows as a `.marker`, a ring with its name, hidden until placed) and tapped with `clickGame` by the zoom pad's **q.Save** / **q.Load** (`src/quick-save.ts`; disabled until placed or with no game picked). The portrait runs a second `startTextReader` on the name box (with `retryFlattened`: a read that comes back as garbage is retried with `cropForOcr(…, 'flatten')`, which removes the background by subtracting a blurred copy; Aokana's white name on a light gradient plate reads at ~20% normally and 96% flattened, while flattening makes ordinary text worse; flattened reads need `MIN_FLATTENED_CONFIDENCE` (80), since flattening turns edges in the art into stroke-like marks: a hair outline read as "7 WN" at 55) (`setSpeaker` → main's `src/line.ts` keeps the latest read and the shown speaker, broadcasting `speaker-changed`, cleared like the line. Every change of name, appearing, going or switching, only shows when the text line changes, so the name always belongs to the line on screen; a name read within `SPEAKER_CATCH_UP` (2s) of a line change belongs to that line) and shows it in `#name-tag` on the message window's top-left corner: an accent pill overlapping the window's top edge (hidden while empty, i.e. narration; You and Me and Her shows plain text, Miyuki's Realm the bevelled frame).
