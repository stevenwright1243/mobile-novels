# The portrait view

How the streamed portrait (`portrait.html`, `src/portrait.ts`, `portrait.css`) lays out and draws the game, and its reader screen, history log, Menus mode and Menus sheet. Sizes and positions are recorded in [portrait-layout.md](../portrait-layout.md); themes and styles in [styling.md](styling.md); Auto in [auto-play.md](auto-play.md).

## Drawing the zones

Each canvas is resized by a `ResizeObserver` to its box size × `devicePixelRatio`. Crops are placed by `placeInZone()` (`src/zone-view.ts`, shared by the portrait and the picker) from a `ZoneView`: `fill` blends from show-all (0) to fill/cover (1), `x`/`y` line the picture up (which part shows when trimmed, where it sits when there's space around it). Both zones share one grid cell: the background fills the portrait and the text panel (a gradient scrim) lies over its bottom, so the text never moves the background. The background picture never moves because of the text (the user treats that as a bug): it's placed in the full canvas and the window always lies over it. The window's text size is `--chosen-font-size` (= `--base-font-size`, the 100% size defined once at the top of `portrait.css`, × `--text-size`), and its height (a 3-line `min-height`, `--three-lines`, registered with `@property` as a length so it reads back in pixels; in Text position Top the window fits its text instead, never squeezed below 3 lines or its text: `calc-size(max-content, clamp(<1 line>, size, var(--three-lines)))`, at least 1 line so an empty window isn't a thin strip) is worked out from it. The background uses `BACKGROUND_VIEW` (`src/zone-view.ts`): centered left to right; its `width` (75%) and `y` (20% down) are only the defaults for the game's own `backgroundWidth` (how much of the background's width shows, 50–100%; the **Portrait width** sliders) and `backgroundY` (the **Portrait height** sliders). `ZoneView.width` zooms by that share (`placeInZone()`), so a given % looks the same in every game; other views zoom by `fill`. (The zoom used to be fixed for every game, showing 74–79% of the width; the user chose a per-game slider.) Older profiles' saved `backgroundView` is dropped on load. The picker's "Portrait view" box (`src/background-view.ts`) outlines the visible part using the zone size the portrait reports via `setBackgroundZoneSize`. Space around a zoomed-out background is filled with a blurred, darkened copy (drawn tiny and stretched, for speed; shrunk with `imageSmoothingQuality = 'high'` and blended over the last few frames, `BACKDROP_BLEND`, so tiny changes in the capture don't make it shimmer).

## History log and shared looks

Main also keeps the **history log** (`src/line.ts`, with the line and speaker; tested in `line.test.ts`): the last 30 non-empty lines, each with its speaker (`HistoryEntry`, `getTextHistory`; a speaker confirmed within `SPEAKER_CATCH_UP` of a line is taken as that line's, since the two boxes are read separately), kept when the game's window closes and cleared when another game is picked. The portrait's Log button (top-right in Menus mode; the reader has Auto there) opens it as a native `<dialog>` (`showModal()`, `src/history-log.ts`): a snapshot shown one line at a time, newest first, with big ◀ / ▶ buttons and "Return to game".

The frosted look is a shared `.glass` class in `portrait.css`; the corner pills share `.corner-button`.

## Menus mode and the Menus sheet

The top-left **Menus** button is raw mode (3c): a `raw-mode` class on `.portrait` gives the background zone the whole portrait and hides the text zone, and `zoneRegion()`/`zoneView()` in `portrait.ts` make the background zone show the full client area with `SHOW_ALL`, so taps map 1:1 through the same `placeZone()`. It's session-only (not saved).

Its game can be zoomed (`src/game-zoom.ts`, session-only, reset on leaving Menus or picking another game): a pinch, the mouse wheel (Artemis's trackpad mode turns a two-finger drag into the wheel) or, once zoomed, a drag; `placeZone()` applies the zoom through `zoomedPlace()` (held so the game always covers `#game-slot`, drawn clipped to it), so drawing and `tapToGame()` stay in step, and a gesture's click is stopped in the capture phase, like `drag-scroll.ts`. The canvas has `touch-action: none` in Menus mode.

At the top of the Menus sheet, above `#sheet-tools`, the **zoom pad** (`#zoom-pad`, `src/zoom-pad.ts`) does the same a step per tap, with **q.Save** over **q.Load** on its left (`.quick-buttons`, see the spots above): zoom in / out on the right beside the d-pad (by √2, so two taps double it and four reach the 4× most), the d-pad moving half of what's shown per tap (`zoomStep`, `moveStep`; `ZOOM_STEP`, `MOVE_STEP`), and in its middle the zoom level, which goes back to the whole game when tapped; buttons that would do nothing are disabled from `zoomState()`, refreshed on every change (`onZoomChanged`). (A 1× pill over the game's corner was tried first and taken out: it didn't respond.)

In it the portrait's grid becomes `buttons`/`game`/`sheet` (side by side in landscape): the background canvas still fills the portrait (blurred backdrop), but the game is drawn into the box of `#game-slot` (`slotInCanvas()`; its height from `--game-aspect`, set from the capture, at most 55dvh), and below it the **Menus sheet** (`#menus-sheet`, `src/menus-sheet.ts`) picks the look with big buttons (headed Themes, Icons and Borders): themes drawn in their own theme, moving arrows, small message windows with each border, and a sample message window in the current look.

At the sheet's top, sharing a row half and half (`#sheet-tools`), are **Screenshot** (right; `screenshot-game`→`pressKey(hwnd, VK_F12)` in `win32.ts`: brings the game to the front and presses F12, the user's Steam screenshot key, as real input, since every game is a Steam game for now; non-Steam games are for later) and the **Full-screen text** switch (Off / Auto / On, Auto by default; `src/page-mode.ts`, session-only like Menus, since games switch between full-screen text and a text box; **Auto** is `src/auto-page.ts`: while the text box has been empty for `QUIET_BOX` (0.8 s), the page reader also runs (`probesPage`), and a page read that's the game's story text switches to the page; while on the page, the text box reader keeps running (`probesBox`), and a line of game text there that isn't part of the page (`isPartOfPage`, for games whose page covers the box) switches back, as does the page staying empty for `QUIET_PAGE` (1.5 s). "The game's text" is main's `is-game-text`→`isGameText` in memory-text.ts: a sentence-sized paragraph (`MIN_CHECKED_LETTERS`, 25) of it found in the game's memory, so art read as text and menus aren't (tested on Katawa Shoujo: its full-screen page yes, in 2 s; the text box's junk, menu words and made-up sentences no). Where memory can't tell (switched off, or a game like Steins;Gate), a page read counts if it's clearly prose (`looksLikeProse`: 2+ lines, 80+ letters). One check at a time, the latest read waiting; the page read Auto switched on is shown from `latestPage()`, since the page reader won't send it again): the `page-mode` class shows `#page-view` (glass with the message window's border, holding the scrolling `#page-text`) in place of the line and name, growing up to the background picture's bottom edge (`--picture-bottom`, reported by portrait.ts from `placeZone()` each frame outside Menus mode), but always allowed 45dvh and never past the corner buttons, then scrolling (by finger,`touch-action: pan-y`, or by mouse drag in page-view.ts, since phone taps may arrive as mouse input; a drag's click is cancelled so it doesn't advance the game; the top edge fades once scrolled, and the arrow hides while scrolled back from the end); the text and name readers rest (`active` option of `startTextReader`) and a third reader reads the `page` region with `page: true`, which keeps the paragraphs `readText` returns (`paragraphs`: lines split where the gap is over `PARAGRAPH_GAP`, 0.4, of the usual line height; in Katawa Shoujo 0.22 inside a paragraph, 0.68 between) joined by a blank line. `src/page-view.ts` compares each confirmed page with the last (`whatsNew`: paragraphs at least `SAME_PARAGRAPH`, 85%, alike by edit distance count as the same, so a re-read with a letter wrong adds nothing; a grown last paragraph adds only the added part; anything else is a new page), sends each new paragraph to main with `setTextLine` (so the history log gets it once), dims the ones already read (`.read`) and scrolls to the new text (to its start if it doesn't fit). Taps on the page click the page region's bottom-right corner (`PAGE_CORNER`), where the mouse pointer (the capture shows it) stays off the text. Turning it on clears the speaker.

At the bottom of the sheet, a **Sizes** drop-down (`<details id="sizes">`, its content in `.sizes-body`, a grid: a `<details>` doesn't lay out its children as one in every Chromium; the content is written once in `src/sizes-panel.ts`, which fills the empty `.sizes-body` of either page, and its sample is drawn by `src/sizes-sample.ts`, given the screen's size: this window's in the portrait, the portrait's reported size (`setBackgroundZoneSize`, now in CSS pixels) in the picker; the arrow shapes are in `src/arrow-shapes.ts`) holds Text size, Name size, Portrait height, Portrait width and Button size sliders in 5% steps (`step="0.05"`, values rounded to whole percents; a finer value set in the picker shows as it is until moved), with the track filled up to the thumb (`--fill`) and a 48px-tall input for fingers. The portrait's sizes live in `src/portrait-sizes.ts` (`textStyle`, `backgroundY`, `buttonSize`: `get`/`listen`/`set`), since main passes a `set-*` change only to the other windows, so changes made in the sheet reach the portrait's own listeners there. The game's sizes are unsaved profile edits like the picker's, and so is the button size (the user's choice): it's still an app setting, the same for every game, but main keeps the size in use (`settings.buttonSize`) apart from the saved one (`savedButtonSize`), counts a difference as an edit (`hasEdits`), writes it only on Save (`saveCurrentProfile`, which now also works with no game picked), and every other settings write uses `persistSettings()`, which writes the saved size. **Save**, **Reset** and **Default** sit side by side, centered, at the bottom of the drop-down (`#sheet-actions`), always shown while it's open, but disabled (dimmed, blurred 1.5px, no pointer events) when they have nothing to do: Save and Reset until there are edits (`get-save-state`/`save-state-changed`), Default while every size already matches the defaults, which it sets as ordinary unsaved changes. The defaults (the user's choice: text and name 100%, portrait height 20%, width 75%, button size 100%, text position Bottom, padding 0%) live in `src/default-sizes.ts`, shared by profiles.ts (a new game's sizes, and laid over older profiles for values they lack, so a profile saved before text position existed opens with Bottom), settings.ts (button size) and the Default button; Reset (`revert-edits`→`revertEdits()`) lays the saved snapshot back over the profile and puts back the saved button size, broadcasting each to every window. "Don't save" in the unsaved-changes dialog also puts the button size back. The game's sliders are disabled with no game picked. The Sizes panel follows `button-size-changed` in both windows.

After Button size, **Text padding** (`TextStyle.padding`, 0–1 in 5% steps, default 0, per game): extra space on the side the window grows from, `--text-padding` × 20dvh (`--text-extra`): added to `--gap-bottom` with Bottom, to the gap under the picture (`--zone-top`) with Top, where it also counts in the Portrait height cap (`TEXT_PADDING_SHARE`); 0 keeps the usual gaps.

Under the sliders, **Text position**, an on/off-style switch (`#text-position`, `role="switch"`, labelled "Bot" / "Top"; the words beside it toggle it too; sized in the sheet's text size, 2.3em × 1.3em; it drops under its name when the column is too narrow): `TextStyle.position` (`TextPosition`, default `'bottom'`, so per game, saved and reset with the rest), set as `data-text-position` on `.portrait`. Bottom is the usual layout (the window at the screen's bottom, growing upward); Top hangs the text zone just under the picture (`margin-top` from `--picture-bottom` plus `--gap`, never above the corner buttons' row, with `max-height` to the screen's bottom and laid out as a flex column, so the message window shrinks to the room left, down to 3 lines (or its text, if shorter; it fits its text when there's room), and then scrolls (`overflow-y: auto`; dragging too, via `src/drag-scroll.ts`, shared with the full-screen page: `dragToScroll()` and `updateScrollState()`, which marks a box `scrolled`/`reading-back`; the arrow hides while the window is `reading-back`; a new line starts scrolled to the top). To guarantee those 3 lines, **Portrait height is capped** in Top: `updateBackgroundYCap()` in portrait.ts works out each frame, from the picture's height on screen and the room the zone needs at 3 lines (gap, padding, name tag less its overlap, the window at 3 lines, `--three-lines`; measured from those parts on the reader's zone, or the Sizes sample's in Menus mode, not from the zone's own height, which is squeezed when the picture is too low), the highest `backgroundY` that leaves that room, into `backgroundYCap` (portrait-sizes.ts; not a setting, not sent to main). The background is drawn at `min(backgroundY, cap)`, and the Menus slider shows and stops at the cap; a higher value set in the picker is kept but held at the cap. Bottom has no cap. (Before: a 60dvh cap, then a cap at the screen's bottom with no scrolling.), so it grows downward, and keeps the name tag's room while there's no name (`visibility: hidden` instead of `display: none`), so a name coming or going never moves the window's top edge. The text zone is `position: relative`, so the arrow is placed in the window's corner wherever the zone sits (it used to measure from the screen's bottom, which only matched for Bottom). In Menus mode `drawSample()` reports `--picture-bottom` for the reader (the reader's own drawing doesn't then). Beside the sliders while it's open,`#sizes-sample` shows a live miniature of the reader screen:`.sample-screen` is the reader's layout at full size (100vw × 100dvh, so every `vw`/`vmin`/`dvh` size in it is the real one) holding a canvas, the corner buttons and a `.text-zone` with the current line and name (stand-ins when there are none), shrunk with `scale` to the height of the slider column beside it (their own height,`slidersHeight()`; the column spreads its rows over that height, so the Text position row lines up with the sample's bottom; at most 50% of the drop-down's width, `MAX_SAMPLE_SHARE`, and slider names don't wrap, so the two can't feed each other) (`fitSample()` in portrait.ts); portrait.ts draws the picture into it each frame at the game's `backgroundY`. The reader's rules in portrait.css (and the You and Me and Her haze in theme.css) match `:is(#text-zone, .text-zone)`, `:is(#text-line, .text-zone .message-window)`, `:is(#name-tag, .text-zone .name-tag)` and `:is(#next-arrow, .text-zone .next-arrow)`, with the same specificity as the IDs alone, so the miniature gets the same styles. Opening the drop-down scrolls the sheet to it.

Under Sizes, a **Visual Novels** drop-down (`<details id="visual-novels">`, `src/visual-novels.ts`, sharing Sizes' summary styles) lists the saved profiles (`list-profiles`) as chips; tapping a running one calls `selectSource`, like a picker card (with the same unsaved-edits dialog), and the one being played is marked `aria-checked`. Tapping one that isn't running starts it (`launch-game`: a Steam game through Steam, `steam://rungameid/<id>`, its app ID found by `steamAppIdOf()` in `src/steam.ts` from the library's `appmanifest_*.acf`, since started from its .exe it restarts itself through Steam and Aokana's second copy then failed with "already running"; any other a `spawn` of the saved `exePath`, detached, in the exe's own folder), and main picks it (`selectGame`, the `select-source` handler's body) once the 2-second windows check sees its window (`pendingLaunch`, for a minute; picked again if that window closes while another of the game's opens, e.g. a splash screen).

A centered **Close** button at the bottom (`#close-game`, labelled with the game's title) force-closes the game played before the current one (the user's choice, for switching between two games): of the other running games, the one picked last (`pickedAt`, set in `selectGame`), or if none was picked, the one first seen open last (`openedAt`, a map main keeps from that same windows check; games already open when the app starts count as opened then), both sent in `ProfileSummary`; with no other game running, the current one with `taskkill /PID … /T /F` (`close-game`, `processIdOf()` in `win32.ts`), with no confirmation.

Under it, an **Input Settings** drop-down (`<details id="input-settings">`, `src/input-settings.ts`, which fills the empty `.input-body` of either page, like Sizes) holds the click method as a Messages / Mouse switch (`#click-method`, the same `.toggle-switch` as Text position;`set-click-method` now broadcasts `click-method-changed` to every window, the sender included), an unsaved profile edit with its own Save and Reset (`.save-button`/`.reset-button`, wired with Sizes' in menus-sheet.ts), and under them **Bring game to front** (`bring-game-to-front`→`bringToFront()` in `win32.ts`: restores it if minimized, then `SetForegroundWindow`) and **Send game to back** (`send-game-to-back`), disabled with no game picked. Main broadcasts `source-selected` to both windows, and the picker shows a pick from either in its `onSourceSelected` handler (`showPicked`), not in `pickWindow`. Full-screen text is detected automatically by Auto (see above).
