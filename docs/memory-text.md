# Exact text from the game's memory

How `src/memory-text.ts` finds the line on screen in the game's memory and follows it, so lines show exactly, often before OCR has read them. Codecs, including a game's own learned alphabet, are in `src/text-codec.ts`; the Win32 memory reads are in `src/win32.ts`.

## Finding and following the line

**Exact text from memory** (`src/memory-text.ts`, per game, `textFromMemory` in the profile, on for new games; the switch and its status in Input Settings, `set-text-from-memory` / `memory-text-status-changed`): games keep the line they show in memory, at addresses that change each run.

**Finding it:** when OCR confirms a line, main searches the game's writable private memory (read-only: `openForReading`, `writableRegions`, `readMemoryAsync` in `win32.ts`, 0.3–1 s, in the background) for up to `NEEDLES` (8) runs of its plain-letter words (OCR may have garbled any of them; `MIN_NEEDLE` 12 letters, or `MIN_SHORT_NEEDLE` 8 when nothing that long is left) as UTF-16 and UTF-8, noting what each copy holds; when a later line comes, every copy that has **changed** to it (`MATCH`, 60% alike by letters) is followed (only changed ones: OCR reads the same line a little differently each time, and the game's script, which never changes, matches every read of it; a read `SAME_LINE`-alike to the last one searched for isn't searched again).

**Until then, each line is matched on its own** (status `matching`, "Found: each line OCR reads is corrected from the game"): every search also takes the copy that best matches OCR's read (`bestCopy`: formatting codes stripped by `clean`, Unity's `<alpha=#f8>` typewriter redraws and Ren'Py's `{w}`, plus undecodable and invisible characters; the line's start looked for around where a run of its words puts it, since a copy can have other text before it, like Aokana's script with every language's version in a row) and sends it as a correction (`onMemoryCorrection` → main replaces the shown line, and its history entry, if OCR's read is still shown); a re-read of a corrected line keeps it (`corrected`). The quote marks at its ends follow OCR's read (`withQuotes`: Ren'Py draws a character's quotes around text stored without them, and a copy can carry a stray one). Each search runs whatever the last search's copies did (in engines that never rewrite a buffer, none ever changes).

**A followed copy has to keep proving itself:** it's only taken up if it holds all of OCR's read (`holdsWhole`: no letters from another writing system, within 5% of its length, the first 10 letters 80% alike), and when OCR later reads clearly more of a line than the copies hold, starting the same way (`isPartOf`; Ren'Py's typewriter effect builds the line a letter at a time as new strings that can reuse the same memory, so Katawa Shoujo once locked onto "I ponder … snowfall graduall" for "As I ponder … thickens."), OCR's read shows, and `MAX_WRONG_FOLLOWS` (2) in a row stop following for the run (`noFollowing`), back to matching line by line. Characters from a writing system the read doesn't use, or half a UTF-16 pair, are trimmed off the match's ends (Ren'Py's object header read as text, "踁This is…"), and don't count as a word the line starts inside of. This is how engines that never rewrite a buffer get exact text: Unity and Ren'Py make a new string for every line.

**Following a pointer to the line** ("Following a pointer to the line" in memory-text.ts): those engines still keep a pointer to the string on screen, set to each new line's string. After each line matched one by one (`lookForPointers`, from the search, `nextInScript` and `catchUp`), `findPointers` finds the strings of just that line (`letters` equal; `textStart` skips a string's length read as its first character, "%I almost…") and every pointer to them (any value from the text back to `MAX_HEADER`, 64 bytes, in 4-byte steps, so the string's header is learned: Mono's 12 bytes in 32-bit, 20 in 64-bit; the pointer's size from `pointerSizeOf()` in win32.ts, `IsWow64Process`), as `pointerCandidates`: `Spot`s with `pointer: { size, offset }`, read through by `textAt` (`pointedTo`). `followChangedCopies` checks them with the copies; one that moved on to the next line, its string just the line (nothing after it, so the script's entry with every language isn't followed), is followed as the buffer (its new string all new, not `newLine`, and never `showWhole`), so memory leads. `MAX_POINTER_SEARCHES` (5) looks that find none stop it for the run; following resets the count. Aokana: found on the second line (9 pointers in 0.7 s; the two to the English line are followed), then every line exact from memory, often before OCR has finished reading the typewriter effect. Not yet tested: a scene change (the pointer may move; the buffer is dropped and looked for again), Katawa Shoujo (Ren'Py, where `noFollowing` may stop it).

Tested per engine: Aokana (Unity with Mono, 32-bit, 0.15–0.8 s a search), Katawa Shoujo (Ren'Py, 0.8–2 s), The Colorful World (FVP: follows its buffer).

Steins;Gate (MAGES) keeps no line as UTF-16 or UTF-8 but in **its own alphabet**: each character a 2-byte big-endian code into its font ("a" = 0x80a4; capitals at another offset, spaces and punctuation in the font's own order). Text is read through codecs (`src/text-codec.ts`: `UTF16`, `UTF8`, and `AlphabetCodec` for a learned `Alphabet`, saved per game in `settings.json`'s `alphabets` by profile ID, straight away, via `onAlphabetLearned` → main; `startReading` gets it back). After `EMPTY_SEARCHES_TO_LEARN` (2) searches with no copy, `learnAlphabet` does a **relative search** (`relativeSearch`): a long lowercase word from OCR's read, looked for as its pattern of steps between codes (fonts keep letters in order), in 2-byte big- and little-endian and 1-byte codes; a find counts if most of the line's lowercase letters fit around it (`fitLine`, `MIN_FIT`), and the line then teaches the codes of characters next to ones already known (`learnFromLine`, passes repeating, so it spreads from letters to spaces to a lone "I"). Later lines matched in the alphabet with codes not yet known teach those too (`refineAlphabet`, then decoded again: "can't", "?"). Steins;Gate: learned in 0.6–0.8 s. A saved alphabet is searched from the first line (`alphabetFound` starts true, reset if it finds nothing before it has found text this run: `alphabetAssumed`). The alphabet's decoding skips **markup** inside a line (`markupEnd` in text-codec.ts: a run of `MIN_MARKUP` (2) to `MAX_MARKUP` non-text codes, at least one not zero (a lone code ends the line, so one ending in a letter or comma isn't joined to the next), after a letter, digit, space or comma and before a known character; Steins;Gate colours a word with 0x0482 0x0000 … 0x0480 0x0000), and finds a string's ends past it (`stringStart`, `stringEnd`).

**Following the script:** where lines are matched one by one, main keeps where the last one is (`lastLine`, set from the match's copy), and `lineForRead` first checks that string (only when `SAME_LINE`-alike: more of the same line read; a new line can be much like the last) and the `NEXT_LINES` (4) after it (`nextInScript`, one 4 KB read) before any search (but after checking whether the last search's copies changed to the line, `followChangedCopies`, so a line buffer is still found and followed): instant, and in a game's own alphabet (strings ended by a code, 0x03ff) it also takes a line OCR read only the start of (`isNextLine` with `startOnly`: "“What!?" when the rest is in red OCR can't read, or a line still being typed), its unknown codes learned from that start (`learnFromLine`, lined up with the string's own codes, markup left out and nothing past its end: `textCodes`, also used by `refineAlphabet`) and a closing quote mark from its last code (`learnClosingQuote`, only right after `.`, `!`, `?` or `…`, since a code learned wrong stays wrong), its end kept as memory has it (`withQuotes` with `atEnd` false). In UTF-16/UTF-8 a string can run on into an older one's leftovers ("rude?#8c> handmade soba…" in Aokana), so there the line is cut by `endFor` and must match all of the read. Where only lines are matched, a search across all of memory tries the first `FIRST_NEEDLES` (2) runs first, then the rest if they find nothing. A line OCR reads while a search runs waits (`waiting`) and is looked up when it ends (`catchUp`: the next in the script, or searched), so it isn't skipped. Lines never start with `NOT_A_START` marks (the end of a name stored before the line, "【Girl】：" in Aokana, or The Colorful World's `` ` ``). Once the alphabet has found text in a run and UTF-16/UTF-8 haven't, only it is searched (`codecsOf`; not before, since a saved alphabet may belong to another game with the same .exe name, "Game.exe"), and where lines are matched one by one (`copiesOf`), the stretches of memory copies were last found in (`hotRegions`) are searched first: Steins;Gate's lines in ~30 ms instead of 5 s over its 839 MB. `MAX_EMPTY_SEARCHES` (5) searches in a row with no copy (and no alphabet being learned) stop the searching (status Not found), and searches pause between runs (`breather`) so main's requests aren't held up. Work still under way for a game no longer read (another picked, or switched off) stops before reading memory or reporting anything (`stale`: the closed handle may be given to the next game).

**Then memory leads:** main checks the copies every `POLL_EVERY` (150 ms) and shows each new line as soon as the copies agree on it (`onMemoryLine`→`showLine` in main), even when OCR can't read it at all (The Colorful World's "No, I haven't.", "......"). A copy that changes alone, or doesn't follow within `FOLLOW_WAIT`, is dropped (the game moved that string; its old memory gets reused, reading as "慮猧猠畱物"), and so is a line with letters from a writing system the game's lines haven't used (`writingSystems`; learned from the first line and from lines two copies agree on). A new line overwrites the start of the last one, so the line ends where the two texts stop agreeing, counted back from the end, then on to the next end mark (`newLine`); the end mark is the mark after the first line (The Colorful World's `~`), or learned later; inside a line the same mark is the game's own line break ("I think I~finally") and becomes a space. That game's fixed-size buffer holds about 94 characters, so a line with no end mark is cut off: `showWhole` searches memory for its exact start and takes the shortest longer copy.

**OCR after that:**`set-text-line` (`lineForRead`) ignores OCR's read when it's alike to the line (`LOOSE_MATCH`, "Vow dem" for "You don't?"), within `OCR_CATCH_UP` (3 s) of a new line, empty, or under `MIN_OCR_ONLY_LETTERS` (8) letters ("A 4" from a scene change); otherwise OCR's read shows (text the game didn't put there), and `MAX_MISSES` (5) of those in a row drop the copies and search again. Before the line is found, OCR's read shows as before.`readMemory` reads only up to the end of the address's region when the full read fails (the copy can sit near a region's end).

**Names** (`nameForRead`, from main's `set-speaker`): the game also keeps the speaker's name in a copy rewritten at each new speaker (The Colorful World: `"  Kana~"` in UTF-16, then `"  Yuuma~"`, each with two spaces before it), found like the line: copies of a name the name box's OCR read (`findNameCopies`, whole strings only, since the script holds thousands of each name), then the ones that changed to the next different name it read. A name copy keeps the last speaker during narration, so OCR still decides whether a name shows ('' stays ''); memory gives the spelling when the two are `MATCH`-alike ("Shlnku" → "Shinku"), else OCR's read shows, and `MAX_MISSES` of those drop the copies. (The game's backlog keeps each line with its speaker before it, but only lines already seen, so it can't name a new line; tried and dropped.) Name searches stop after `MAX_SEARCHES` (6) per run without finding a copy. Debug mode logs searches, copies, each new line and name.

Tried first and dropped: Textractor (5.2.0) skips The Colorful World's FVP engine ("vnreng: IGNORE FVP"), its hook search finds no lasting hook, and its Clipboard stream picks up whatever the user copies; its default Google Translate extension would send lines online.
