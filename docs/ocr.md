# Reading the text box (OCR)

How the app reads the game's text from the picture: OneOCR, the clean-up rules in `src/ocr.ts`, the readers in `src/text-reader.ts`, and the debug tools and OCR bench used to check them. Exact text read from the game's memory is in [memory-text.md](memory-text.md).

## Debug mode

`npm run start:debug` runs the app the same, in debug mode (`--vn-debug`; not `--debug`, which Electron rejects as an old Node flag): every OCR read, its confidence and time, is printed in the terminal, and the picker shows its **Debug** tools (the OCR test button, **Save as OCR test…**, **Show OCR tests**, and a **Log OCR reads** checkbox that quiets the per-read lines until the next start; `isDebug()`). The portrait's Menus sheet then has a **Debug** drop-down too, last (`<details id="debug">`, `src/debug-panel.ts`), so it can be done from the phone: **Save as OCR test** in one tap (the portrait can't be typed in, being `focusable: false`, so the test is saved with what the app showed as its expected text and `unchecked: true`; fill in the right text from the frame, by looking at the PNG, then take `unchecked` out; the bench skips and lists unchecked tests), **Read the text box now** (one read, its image and result) and the Log OCR reads switch. Both windows' tools share `src/ocr-debug.ts` (`readTextBoxOnce`, `grabClientArea`).

## Trying OCR changes live

While the user has `npm start` running, edits to renderer files (`capture.ts`, `text-reader.ts`, the pages) hot-reload into their open app, so mid-work they're seeing whichever version is on disk; main-process files (`ocr.ts`, `main.ts`, `preload.ts`) need a restart (`rs`, or stop and start again for `start:debug`). Tell them when an OCR change is being tried live. Their sightings are useful but can mislead: a running app may mix new renderer code with an old main process. A bigger re-read of failed reads looked like it fixed Aokana's "N..." live, but that app still ran an older `ocr.ts`; the real frame, saved as an OCR test after a restart, read right with or without it, so it was taken out. Confirm with a saved frame (and a restart) before keeping a change on what was seen live.

## The OCR bench

`npm run ocr-bench`: runs the text reader on every saved **OCR test** and scores it (exact reads, letters wrong, text made up in empty boxes, lines missed). `npm run ocr-bench -- <commit> <commit>` also builds and runs those commits side by side; `--only <name>` filters tests, `--scales 1` runs full size only (default 100, 80 and 60%), `--verbose` prints every OCR attempt. Tests are saved from the picker in debug mode (**Save as OCR test…**: the game's client area as a PNG at capture size, the regions, and the correct text, prefilled with what the app shows; `src/ocr-tests.ts`) into `%APPDATA%\mobile-novel\ocr-tests\`, not the repo (it's public; the frames are game art). The bench (`tools/ocr-bench/`) bundles each version's `ocr.ts`, `oneocr.ts`, `win32.ts`, `capture.ts` and `text-reader.ts` with rolldown (versions from before OneOCR need tesseract.js, which is no longer installed, so they can't be compared) and runs them in a hidden Electron window the way the portrait does (each test at 100%, 80% and 60%). Run it before and after any OCR change, and add a test whenever the user reports a misread. A run takes about a minute (~10 s of it OCR) and shows a dot per read as it goes; an OCR error (OneOCR not loading) stops it at once with the reason, instead of each test waiting out its 60 s timeout. Run it in the background with the watchdog (see the long-running commands rule in ~/.claude/CLAUDE.md): `--match "tools/ocr-bench/run.mjs"`, its output file as `--log`, `--stall 90`. The project skill `ocr-tests` (`.claude/skills/ocr-tests/SKILL.md`) walks through checking tests the user saved: filling in what each frame shows, finding the cause, and fixing it with the bench before and after. A test can also hold a page of full-screen text (`page` region and `expectedPage`, paragraphs separated by a blank line; the dialog's **Full-screen text** box), scored with its paragraph breaks kept (as ¶); `katawa-shoujo-nvl-page` was made from a screenshot the user shared (its mouse pointer reads as a stray word: a known miss).

## The engine and the clean-up rules

OCR runs in main with **OneOCR**, the OCR engine inside Windows 11's Snipping Tool (`src/oneocr.ts`: `oneocr.dll` through koffi, `recognize()` returning lines of words with boxes and 0–100 confidences; undocumented, its functions and model key from the `oneocr` Python package, github.com/AuroraWright/oneocr). Windows won't load a DLL from a Store app's folder into another program (access denied), so on first use its three files (`oneocr.dll`, `oneocr.onemodel`, `onnxruntime.dll`, ~115 MB) are copied from the Snipping Tool's folder (`packageFolder()` in `win32.ts`, by package family, no PowerShell) into `userData/oneocr`, again when the Snipping Tool's version folder changes (`from.txt`), and loaded with `loadLibraryNextTo()` (`LoadLibraryExW` with `LOAD_WITH_ALTERED_SEARCH_PATH`, so its `onnxruntime.dll` is the one beside it, not Windows' own). Reads run on koffi's thread (`.async`). If it can't load, every read fails and main shows the reason once in a message box (`read-text`); there's no fallback engine (the user's choice; docTR via ONNX Runtime was the runner-up).

It replaced tesseract.js in Oct 2026 after a shootout of 28 engine setups on the OCR tests (branch `ocr-shootout`, `tools/ocr-shootout/RESULTS.md`): in the app's bench 0.3% of letters wrong against Tesseract's 6.2%, no line missed against 24, in half the time; vision-language models (Qwen3-VL, GLM-OCR, PaddleOCR-VL…) read as well but are 10–30× slower and make up text for empty boxes.

Renderers crop the box to a PNG as it is (`regionInVideo()` + `cropBox()` in `capture.ts`, high-quality smoothing since region edges fall between pixels) and send it with `window.vn.readText`; no enlarging or black-on-white preparation: that was Tesseract's, and it broke OneOCR's reads of outlined text (7.9% wrong). OneOCR reads bare art as nothing (all 42 empty-box reads), so the many junk filters Tesseract needed (word height, the arrow's corner, wide gaps, the 'white' and 'flatten' second reads, digits read as letters) were taken out after none fired once in a bench run; see git history before Oct 31 2026 if a new engine ever needs them. `readText` (`ocr.ts`) keeps only what fires with OneOCR: `joinMarks` joins a word of only dots, or a quote mark ending a line, to the word before it, and one starting a line to the word after ("Ah ..." → "Ah...", "... I see" → "...I see"); `withoutDoubles` keeps only the longer of two lines overlapping by over `MAX_LINE_OVERLAP` (text at the box's top edge read twice, "Most" over "Most people? Who's most people?"); `withoutLoneEnd` drops a lone letter (or `|`) with no punctuation right after a word ending a sentence, at the very end of the read and of each paragraph, never mid-text, where it's a sentence wrapping to the next line ("I tried to read them. I"; drawn tests `synthetic-lone-letter-*`, two with the junk and two that must stay as they are: a wrapped "…them. I / wanted to…" and "plan B"), likewise a word of only dashes, commas, tildes and the like, but not one of only `.`, `!`, `?`, `…`, quotes and brackets; `fixCommonMistakes` turns `|` and a lone "l" into "I" ("I-l did it") and ".." into "..." ("N.."); paragraphs split where the gap is over `PARAGRAPH_GAP` (0.3) of the usual line height. The read's confidence is its words' average. Dropped words are logged in debug mode.

The portrait runs the automatic reader (`src/text-reader.ts`) and sends each confirmed line to main (`setTextLine`). A read counts as text when it's at least `MIN_CONFIDENCE` (40) sure and mostly words (`looksLikeText`; real lines read at 88–99%, but quote marks and dots pull short ones down: "...I see." at 59%, a lone "“" at 8%). The text box's reader (`textBox`) also looks at the box's picture (`measureInk()`, at full size): a box of only a few small, separate dark marks reads as that many dots, one "…" per three, when OCR reads nothing (`readDots()`, flood fill via `markSizes()`; made for Tesseract, which never read "..."); `hasWriting()` (a light box with a text-like amount of ink or a mark bigger than a dot) is Auto's `boxHasWriting`. Words may start with trailing-off dots ("...I") in `WORD`. Main keeps the current line and broadcasts `text-line-changed`, so text sources stay swappable.
