# Themes and message styles

Themes (`src/theme.css`, `src/theme.ts`), the message window's border and arrow (`src/message-style.ts`), and the shared reader styles (`src/reader.css`, `src/settings-panel.css`). The rules for adding a style or a theme are in CLAUDE.md's Conventions; this is the detail.

## Themes, borders and arrows

Styling: **themes** in `src/theme.css` (`@import` ed by `index.css` and `portrait.css`, as are `src/reader.css`, the reader screen's layout, message window, name tag, borders, arrows and corner buttons, in container units (`cqw`/`cqh`/`cqmin` of the nearest `.portrait` or `.sample-screen`, `container-type: size`) so the picker's copy of the screen lays out as the portrait does, and `src/settings-panel.css`, the shared Sizes and Input Settings panels' sliders, switches, chips and Save / Reset / Default), picked with the picker's **Theme** button at the bottom of its sidebar, above the phone status (`#theme-button`, opening the `#theme-menu` popover of theme buttons, each drawn in its own theme, `src/theme-picker.ts`, placed with CSS anchor positioning), the Style page's `#theme` select, or the Menus sheet's Themes (an app setting, `theme` in `settings.json`, saved straight away and broadcast to both windows as `theme-changed`). `src/theme.ts` (imported by `renderer.ts` and `portrait.ts`) sets `data-theme` on `<html>` and loads every theme's bundled font (`@fontsource-variable/nunito`, `@fontsource-variable/eb-garamond`, `@fontsource/share-tech-mono`, `@fontsource-variable/jura`) so they work offline. Plain `:root` is the default, **Aokana** (bright sky blue and white); the others are `:root[data-theme='…']` blocks (each also matches `.theme-sample[data-theme='…']`, so the Menus sheet's theme buttons can each show their own theme): You and Me and Her (`kimikano`), Katawa Shoujo (`katawa-shoujo`), Witch on the Holy Night (`mahoyo`), Hoshizora no Memoria (`hoshimemo`), Steins;Gate (`steins-gate`), Doki Doki Literature Club! (`ddlc`), MiSide (`miside`; its glass has a doodle wallpaper of hearts, flowers, stars and rings in an even, tilted grid) and Miyuki's Realm (`miyuki`: a lavender-grey panel with a bevelled frame on every `.glass`, purple text in Jura). Some themes come with their own border or arrow, picked along with the theme by main, whichever window picks it (`THEME_STYLES` in `src/look-options.ts`, which also lists every theme, border and arrow with its name, for the picker's selects and the Menus sheet): You and Me and Her picks border None and the chevron (its message window is a white haze over the whole text zone, with no glass), MiSide the Hearts arrow, Miyuki's Realm border None and the Triangle; `ThemeName` in `declarations.d.ts`. A theme is a full set of variables: colours (`--accent`, `--accent-deep`, `--accent-pale`, `--ink`, `--line`, `--on-accent`, `--surface`, `--surface-tint`, `--shadow`, `--deep`, `--stage-top`, `--backdrop-tint`, `--rim-light`), and shape and type (`--glass-pattern`, `--glass-blur`, `--font`, `--text-weight`, `--corner`, `--pill`), each explained at the top of `theme.css`. Never hard-code a colour, font or radius in a style; use these variables, with `color-mix(in srgb, var(--accent) 35%, transparent)` for see-through shades (the region editor's overlay colours are the one exception: they stay the same in every theme). The portrait's message window is frosted glass (`backdrop-filter`). Its border effect and "next" arrow are picked in the picker's **Style settings** or the portrait's Menus sheet (`src/message-style.ts`; an app setting, `messageStyle` in `settings.json`, saved straight away; `MessageStyle` in `declarations.d.ts`): border Halo (default), Turning rim, Ribbon or None; arrow Chevron (default), Dots, Triangle, Hearts, Ember, Drop or None. portrait.ts sets them as `data-border` on `#text-line` and `data-arrow` on `#next-arrow` (and on `.portrait`, for `--arrow-width`), and `portrait.css` styles by those. The style rules match `:is(#text-line, .message-window)` and `:is(#next-arrow, .next-arrow)` (and `:is(#name-tag, .name-tag)`), so the Menus sheet's samples share them with the same specificity; theme overrides in `theme.css` use the same `:is()` forms. Both windows follow `message-style-changed`, which main sends to every window, the sender included. The arrow is `#next-arrow`, a sibling of `#text-line` (setting the line's text would wipe anything inside it) holding every arrow shape, of which CSS shows one. The text wraps around the arrow: `#text-line::after` reserves room at the end of the last line from the picked arrow's `--arrow-width` (set on `.portrait[data-arrow='…']`), so a new arrow must set its width there too. The picker's controls are plain selects for now; the user will restyle them later.

## Every style option in every theme

**Every style option must exist in every theme.** When adding a new style option (a border, an arrow, a button look, a new element), build it only from the theme variables, then check it in every theme (light and dark ones differ the most). Where the shared version doesn't suit a theme, add that theme's own version under its `:root[data-theme='…']` block (a new variable, or an override rule), so no theme is left without it. When adding a new theme, define every variable `:root` defines, add it to `ThemeName` and the picker's `#theme` select, and check every existing style option in it. Some options look different on light and dark glass: the Hearts arrow is an accent fill with a deep-accent outline by default (a pale glow blurs into light glass), while dark themes get MiSide's pale glow from one rule in `theme.css` listing them. When adding a theme or changing one's `--surface` between light and dark, add it to or take it out of that list.
